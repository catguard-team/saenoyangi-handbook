# 접근성 트랙 — 6장. 접근성을 첫 쥐돌이로 만들기 (이슈 발견 → PR)

> 다른 오픈소스 프로젝트의 접근성을 개선하는 PR을 보내봅니다. 접근성 트랙의 마지막 챕터입니다.

이 챕터는 **40분~1시간**이면 끝납니다. 본인 페이스로요.

---

## 시작 전에

지금까지 본인의 도구를 정리하시고, 본인 사이트의 접근성을 점검하셨다면, 이제 **다른 프로젝트의 접근성을 개선**하는 단계입니다.

이건 정말 큰 일입니다. 본인이 한 PR이 머지되면 그 사이트를 쓰시는 수천·수만 명의 접근성이 개선됩니다. 한 줄짜리 alt 속성 추가만으로도요.

이게 본인의 **첫 쥐돌이**가 될 수 있어요.

---

## 1. 어떤 프로젝트를 도울까

### 시작하기 좋은 곳

- 본인이 자주 쓰시는 한국 오픈소스 프로젝트
- 자경단의 다른 레포 ([catguard-team](https://github.com/catguard-team) org)
- GitHub의 [`good first issue`](https://github.com/topics/accessibility) 라벨이 붙은 접근성 이슈

### 너무 큰 프로젝트는 천천히

처음에 React, VS Code 같은 큰 프로젝트는 PR이 머지되기 어렵습니다. 작은 프로젝트부터 시작하시는 게 성공 경험에 좋아요.

## 2. 이슈 찾기

### 5장 도구로 검사

- 본인이 쓰시는 사이트를 Lighthouse·axe로 검사
- 문제점 1~3개 골라보기

### 흔한 시작점

| 발견하기 쉬운 문제 | PR로 만들기 좋음 |
|------|------|
| 이미지에 alt 속성 없음 | 매우 좋음 (한 줄 변경) |
| 폼 레이블 누락 | 좋음 |
| 색 대비 부족 | 보통 (디자인 협의 필요) |
| 키보드 트랩 | 어려움 (구조 변경) |

처음에는 alt 속성, 폼 레이블처럼 작은 것부터.

## 3. PR 만들기 — 단계별

### 3-1. 레포 fork

GitHub에서 그 프로젝트 페이지 열기 → 우상단 **Fork** 클릭. 본인 계정에 복사본이 만들어집니다.

### 3-2. 본인 컴퓨터로 가져오기

```bash
git clone https://github.com/본인이름/그_프로젝트.git
cd 그_프로젝트
git checkout -b a11y-fix-alt
```

마지막 줄에서 `a11y-fix-alt`는 본인 변경 작업의 이름입니다 ("a11y"는 accessibility의 줄임말).

### 3-3. 변경 작업

문제가 있는 파일을 열고 고치기. 예를 들어 alt 속성 추가:

```html
<!-- 변경 전 -->
<img src="logo.png">

<!-- 변경 후 -->
<img src="logo.png" alt="회사 로고">
```

### 3-4. 변경 사항 저장 + 푸시

```bash
git add .
git commit -m "a11y: 로고 이미지에 alt 속성 추가"
git push origin a11y-fix-alt
```

### 3-5. PR 만들기

GitHub 본인 fork 페이지 → **Compare & pull request** 버튼 → 설명 작성 → **Create pull request**

설명 예시:

```markdown
## 무엇을 변경했나

홈페이지 로고 이미지에 alt 속성을 추가했습니다.

## 왜

화면읽기 사용자가 로고를 인식할 수 있도록 하기 위해서입니다.
Lighthouse 접근성 점수가 95에서 100으로 올라갔습니다.

## 검증

- Lighthouse 다시 실행
- VoiceOver로 페이지 탐색해서 "회사 로고"로 읽히는지 확인
```

## 4. 리뷰 기다리기

PR을 올리시면 그 프로젝트의 메인테이너(관리자)가 리뷰합니다.

| 응답 | 의미 | 대처 |
|------|------|------|
| **Approve** + Merge | 승인되어 합쳐짐 | 축하드립니다! 첫 쥐돌이 잡으셨어요 |
| **Request changes** | 수정 요청 | 댓글에 따라 수정해서 다시 push |
| **Comment** | 질문·논의 | 친절하게 답변 |
| **Close** (이유 명시) | 거절 | 이유를 보시고 학습. 자경단의 거절도 같은 이유로 |

답이 늦어도 인내해 주세요. 메인테이너분들도 본업이 있으셔요.

## 5. 자경단 jwidori에 등록

PR이 머지되시면 [jwidori](https://github.com/catguard-team/jwidori)에 첫 쥐돌이로 등록하실 수 있어요.

```markdown
제목: [접근성 트랙] alt 속성 PR 머지 — ○○ 프로젝트

내용:
- 무엇: ○○ 프로젝트의 로고 이미지에 alt 속성 추가
- 어디: github.com/owner/repo/pull/123
- Lighthouse 점수: 95 → 100
- 보호자 동의: 받았습니다 (미성년자분만)
```

자경단원 누군가가 검증하시고 갤러리에 등재해 드립니다.

## 6. 절대 잊지 마실 것

### 본인 페이스

PR 한 개를 일주일·한 달에 걸쳐 만드셔도 괜찮습니다. 자경단은 속도를 강요하지 않습니다.

### 거절돼도 자경단원

PR이 거절되어도 본인의 가치는 변하지 않습니다. 다른 프로젝트에 다시 올려보시거나, 자경단 디스코드에서 함께 의논하실 수 있어요.

### 접근성은 권리

접근성은 **새끼고양이의 권리**입니다 ([매니페스토](https://github.com/catguard-team/manifesto/blob/main/MANIFESTO.md)에서). 본인이 PR을 한 줄 보내시는 일은 다른 새끼고양이의 권리를 지키시는 일입니다.

---

## 접근성 트랙은 여기까지입니다

지금까지 0장 준비물부터 6장 PR까지 오셨어요. 정말 큰 길을 오셨습니다.

여기까지 익히신 것:

- 본인 보조기기 정리
- 화면읽기 도구 켜기·쓰기
- 음성·한 손 코딩 도구
- 큰 글씨·고대비·다크 모드
- 자막 자동 생성
- 본인 사이트의 접근성 점수
- 다른 프로젝트에 PR 보내기

**여기서 멈추셔도 충분합니다.** 본인이 본인 환경에서 코딩을 하실 수 있고, 다른 사람의 환경도 함께 개선하실 수 있게 되셨어요.

더 가시고 싶으시면:
- 본인이 만드시는 도구를 자경단 인덱스에 등재 ([§11](https://github.com/catguard-team/manifesto/blob/main/OPERATIONS.md#11-자료-공유-절차-링크-등재) + [§12](https://github.com/catguard-team/manifesto/blob/main/OPERATIONS.md#12-지속가능성))
- 한국어 접근성 자료 작성 (자경단에 정말 필요한 영역)
- 다른 새끼고양이의 멘토 자경단원으로

본인이 가신 길은 다음 분들에게 길이 됩니다. 자경단 디스코드에서 본인 경험을 나눠주시면 정말 큰 도움이 됩니다.
