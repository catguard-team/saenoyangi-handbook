# 접근성 트랙 — 5장. 내가 만든 웹사이트 접근성 점수 매기기

> 본인이 만드신 웹사이트나 다른 사이트의 접근성을 무료 도구로 점검하시는 법입니다.

이 챕터는 **30분**이면 끝납니다.

---

## 시작 전에

본인이 만드신 웹사이트나 자주 가시는 사이트가 다른 분들에게 얼마나 잘 보이는지 궁금하시죠? **무료 자동 점검 도구**로 5분 안에 확인하실 수 있습니다.

이 도구들은 점수만 알려드리는 게 아니라, **무엇을 어떻게 고쳐야 하는지**도 구체적으로 알려줘요.

---

## 1. Lighthouse (Chrome 기본)

가장 쉽고 누구나 쓰실 수 있는 도구입니다. 별도 설치 없이 Chrome 브라우저에 내장되어 있어요.

### 사용법

1. Chrome으로 점검할 웹사이트 열기
2. **F12** 키 또는 우클릭 → **검사**
3. 상단 탭에서 **Lighthouse** 클릭
4. **Categories**에서 **Accessibility** 체크
5. **Analyze page load** 클릭

10~30초 후 결과가 나옵니다.

### 결과 보기

- **0~100 점수** — 100에 가까울수록 좋음
- **개선 사항** — 무엇이 문제인지, 어떻게 고치는지 구체적으로
- 색상 대비, 대체 텍스트, 폼 레이블, 키보드 접근 등 항목별 점수

## 2. axe DevTools (Chrome·Firefox 확장)

Lighthouse보다 더 정확하고 자세한 결과를 얻으실 수 있어요.

### 설치

```
Chrome 웹 스토어 → "axe DevTools" 검색 → 추가
```

무료 버전으로도 충분합니다.

### 사용법

1. 점검할 사이트에서 **F12** → axe DevTools 탭
2. **Scan ALL of my page** 클릭

문제가 있는 위치를 화면에서 직접 표시해 주고, 코드도 함께 보여줍니다.

## 3. WAVE (시각적 표시)

화면에 어떤 부분이 접근성 문제인지 색깔로 표시해 줍니다.

```
wave.webaim.org
```

URL을 입력하시면 해당 페이지를 분석합니다. 직접 화면에 빨간 X, 노란 ! 같은 표시로 알려드려요.

## 4. 한국웹접근성평가센터

한국 표준(KWCAG)에 맞춘 평가 도구도 있습니다.

```
www.wa.or.kr
```

- 정부 운영
- 공공기관 사이트는 이 표준을 따르도록 권고됨
- 평가 보고서 PDF 발급 가능

## 5. 흔한 접근성 문제와 해결

### 5-1. 이미지에 대체 텍스트 없음

```html
<!-- 나쁜 예 -->
<img src="cat.jpg">

<!-- 좋은 예 -->
<img src="cat.jpg" alt="검은 고양이가 책 위에 앉아 있다">
```

### 5-2. 색 대비가 낮음

배경과 글자 색의 대비가 4.5:1 이상이어야 합니다 (큰 글자는 3:1).

도구로 확인:
- [colorable.jxnblk.com](https://colorable.jxnblk.com)
- Chrome DevTools → 색상 선택기에 자동 표시

### 5-3. 폼에 레이블 없음

```html
<!-- 나쁜 예 -->
<input type="text">

<!-- 좋은 예 -->
<label for="name">이름</label>
<input id="name" type="text">
```

### 5-4. 키보드만으로 사용 불가

본인 사이트를 **마우스 없이 Tab 키만**으로 한 번 사용해 보세요. 모든 버튼·링크가 접근 가능해야 합니다.

### 5-5. 링크 텍스트가 "여기 클릭"

```
나쁜 예: 자세한 내용은 [여기 클릭]
좋은 예: 자세한 내용은 [접근성 가이드 문서]에서
```

화면읽기 사용자는 링크 목록만 빠르게 훑어보시는데, "여기 클릭"이 여러 개면 구분이 안 됩니다.

## 6. 점수 100점이 목표가 아닙니다

자동 도구는 약 30%의 접근성 문제만 잡아냅니다. 나머지 70%는 **사람이 실제로 사용해 봐야** 알 수 있어요.

### 사용자 테스트

- 본인이 보조기기를 쓰시는 분이라면, 본인 워크플로우에서 직접 확인
- 그렇지 않으시면, 화면읽기를 켜고 마우스 없이 사용해 보기
- 다양한 사용자에게 피드백 받기 (자경단 디스코드 #도와줘에 도움 요청 가능)

100점이 아니어도 괜찮습니다. **하나씩 개선해 나가는 것**이 중요합니다.

## 7. 자경단 검증 받기

본인이 만드신 사이트가 접근성 좋게 만들어졌다면, 자경단의 [§11 자료 공유 절차](https://github.com/catguard-team/manifesto/blob/main/OPERATIONS.md#11-자료-공유-절차-링크-등재)에 따라 인덱스에 등재하실 수 있어요. 검증 7가지 중 하나가 "차별·혐오 없음"이라 접근성도 자연스럽게 함께 봐드립니다.
